# v2.2.1 software validation and appliance acceptance

The October 14 release selects the dashboard/SNMP/startup candidate, maintenance
corrections and inactive recovery implementation through `cfa931a`. Android
v0.3.0 remains separate; this release does not publish its APK.

## Automated evidence

The October 12 Debian 13 disposable campaign tested implementation `f87d7ff`:
941 Python tests discovered, 937 passed and four native Windows tests skipped;
17 JavaScript tests passed. Windows witness suites passed 15 and 18 tests.
Eight synthetic recovery scenarios passed, with 17 NetworkManager profiles
verified by libnm. Separate isolated SNMP, VLAN isolation/keyfile, ACL and
legacy/VLAN bandwidth checks passed. Compilation, shell syntax and executable
mode checks passed. See the retained [development report](../PCS-RECOVERY-DEVELOPMENT-REPORT.md).

The release process requires the final reviewed PR head to pass all five hosted
CI jobs, then checks the merged main commit. Exact commit IDs and workflow runs
are recorded in the GitHub release. Earlier local results are not a substitute
for those hosted checks.

## Appliance deployment boundary

October 14 preflight found a clean appliance checkout at `86b072b`, native
VLAN mode and active dashboard snapshot, web, Stats API, switch monitor and
uplink-manager services. `acl` and PyYAML were installed. The existing appliance
self-test returned `ALL ENABLED CHECKS PASSED` and `PCS STATUS: OK`.

Runtime dashboard/SNMP/startup implementation is unchanged from that already
deployed candidate. Deployment therefore reconciles installed hashes before
updating the source checkout, preserves a rollback and does not rerun component
installers when installed files already match. The recovery tools are available
from source; no recovery plan is activated, backup restored or network profile
loaded. Final deployment/self-test results are recorded in the GitHub release.

## Remaining acceptance

Publishing software does not establish complete field or recovery qualification.
These remain separate operator-supervised gates:

- Recovery activation transaction, independent rollback and physical reinstall.
- Current VLAN cold boot, no-preferred-WAN startup and actual Mini startup.
- Successful cellular Internet and sustained preferred-WAN recovery.
- Broader physical isolation, throughput, GNSS reacquisition and appropriate RF tests.
- Current-topology FQ-301/FQ-302/FQ-303; historic legacy results retain their scope.
- Real-phone Android upgrade, trust/token retention and LAN/WireGuard acceptance.

No reboot, WAN fault injection, cellular-data trial, RF transmission or hardware
stress is part of this release deployment. Existing policies, credentials and
external switch configuration are preserved. Backup hashes detect corruption,
not authenticity; the compatible encrypted archive format remains unauthenticated
AES-CBC. Staged recovery is inactive and must not be copied wholesale into live paths.
