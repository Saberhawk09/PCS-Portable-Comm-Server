# v2.2.0 validation and appliance acceptance

This release combines the managed-switch migration, optional switch observer,
boot-aware WAN policy, bandwidth manager and previously deployed local fixes.
It preserves existing profiles, service configuration and radio credentials.
Private backups and appliance configuration are not part of the source release.

## Software validation

The release candidate is checked by Linux unit tests, Python compilation,
shell syntax checks, JavaScript tests, Windows witness tests, real libnm
keyfile validation, dual-stack VLAN packet-isolation namespaces, real SNMP
namespaces and bandwidth shaping namespaces. Exact CI results are linked in
the GitHub release. These isolated tests do not certify the physical appliance.

## Live observations before release

The commissioned VLAN topology retained the LAN gateway address, obtained an
Ethernet WAN DHCP lease from a home router, and passed LAN DNS, HTTP and NTP
client checks. The uplink manager selected Ethernet WAN, switched to Wi-Fi
when Ethernet was disabled, and returned to Ethernet when restored. The LCD
and dashboard label correction was verified live. APRS services were restored
without changing their radio configuration. Fresh GNSS fixes were observed.
No USB Ethernet WAN dependency remained in that observed configuration.

The cellular trial automatically activated the existing fallback profile but
produced no verified internet connection. The final self-test at that stage
still reported a Meshtastic GPS-position-update check outstanding, despite
radio/MQTT connectivity. These are unresolved acceptance items, not passes.

## Deferred operator acceptance

The operator retained the VLAN configuration and deferred disruptive testing.
Automatic migration rollback was disarmed after that decision; the private
baseline backups remain available. Retention is provisional and does not
constitute a fully accepted migration or a fabricated commissioning receipt.

- Cold boot and saved-configuration recovery, including fresh GNSS acquisition.
- Physical WAN cable removal/reconnection and successful cellular internet.
- Physical port isolation, including switch-management denial from VLAN 20.
- Actual Starlink internet and wired throughput; no 800 Mbps claim is made.
- Complete appliance self-test, including Meshtastic GPS-position delivery.
- Supervised APRS messaging across both failover directions and RF checks.
- Optional SNMP switch commissioning and verified physical port mapping.
- Legacy fault-injection harness qualification for the VLAN topology.

Bandwidth management is IPv4-only; IPv6 is neither shaped nor counted.
Fresh bandwidth installs are unrestricted until an operator selects a policy.
Publishing this version does not change a commissioned appliance's bandwidth
settings, enable SNMP, reset cellular profiles or trigger disruptive testing.
