# PCS v2.5.0 extended qualification - 17 November 2026

The operator authorized the full remotely recoverable test campaign after the
v2.5.0 release. This report adds evidence to the original
[release validation](v2.5.0-validation.md); it does not turn software starts into
electrical power-cycle tests or establish absolute PPS accuracy.

## Findings and operational restrictions

1. A real fresh Predictive download succeeded, but preparation rejected its new
   cache: the independent date captured before HTTP was older than the manifest
   publication. The follow-up patch revalidates independent time after retrieval
   and again before trial frame selection/reset. It preserves the cache's
   future-date rejection, independent-date requirement, quotas and UTC trust gate.
2. One complete navigation snapshot did not resume advancing kernel PPS within
   the 120-second recovery window. Valid receiver UTC and USB F10N timing returned;
   a separately supervised hot start recovered paired F10P in 29.776 seconds.
   A repeated snapshot completed and recovered normally. The cause is unresolved.
3. Restoring the latest complete 159-entry database over retained navigation
   data was rejected at entry 53, with matching ACK payload and undocumented
   receiver infoCode 255. The actual cold-start boot hook accepted all 159 entries
   from that same backup and recovered paired F10P. These are different starting
   conditions; neither result erases the other.

Unattended database-restore and shutdown-snapshot qualification was therefore
withdrawn for this receiver pending investigation and repeat qualification.
Capture remains available, as does explicitly confirmed manual maintenance.
The original qualification record is saved privately for audit; do not restore
its authorization flags merely to bypass this hold. The normal acquisition
policy file remains absent, retaining commissioned Predictive cache admission.
Shutdown saving stays off. Autonomous and the working Predictive cache remain.

## Remote recovery and fault injection

A root-owned systemd recovery timer protected the campaign independently of SSH.
It restored the original policy/absence, public NTP online state, refresh timer,
ordinary services and journaled UART ownership after an expired heartbeat.
Actual expiration recovery was exercised successfully. Each disruptive operation
used the existing identity-bound owner, maintenance lease and UTC-gate withdrawal.
GPSD was released and reacquired through its control interface; no competing
background serial client was introduced.

| Test | Observed result |
| --- | --- |
| SIGKILL after first real DBD entry, repeated | Production StopPost restored receiver settings and sole GPSD ownership; last valid backup pointer unchanged; paired F10P recovered |
| SIGKILL after first real Predictive ACK | Pending ACK configuration restored; ownership and paired F10P recovered |
| Cancel during actual cached cold acquisition | Job recorded Cancelled; UART returned to GPSD; valid UTC and paired F10P subsequently recovered |
| Shutdown hook with deliberately lost dump completion | Failed safely in 10.728 s; retained complete backup and recovered paired F10P; original shutdown status/policy restored |
| Healthy-timing boot hook | Deferred with zero assistance ACKs; no receiver reset or network retrieval |
| Competing serial admission | Refused while GPSD owned the UART |
| Passive monitor stopped/restarted | Stale/unavailable diagnostics while PPS remained paired; GPSD, Chrony and UTC-gate PIDs unchanged |
| Spectrum collection | Freshness interlock refused an early request; after fresh MON-SPAN, capture/snapshot/automatic timeout/stop passed without timing-service restarts |

The shutdown fault test invoked the actual hook while PCS stayed powered. It
does not replace an electrical power-loss test or a new orderly-shutdown test.
The earlier release's orderly reboot/shutdown evidence remains separately dated.

## Measured acquisition performance

The antenna was not moved by the harness. The operator did not supply a new
antenna/environment annotation. Receiver firmware remained EXT SPGL1L5 6.00,
protocol 40.00. Reset commands were GNSS-only controlled software resets with
hot 0x0000, warm 0x0001 and cold 0xFFFF navigation masks. Receiver configuration,
baud, constellations, flash configuration and PPS electrical settings were not
changed. Reset acknowledgement was not required.

| Hot, cached Predictive | 0.560 | 5.661 | 13.218 |
| Warm, no external assistance | 2.006 | 3.599 | 11.111 |
| Warm, cached Predictive | 1.903 | 78.499 | 86.587 |
| Cold, no external, trial 1 | 56.172 | 118.241 | 128.691 |

The three alternating cold pairs had median receiver TTFF 47.590 s without
external assistance versus 22.666 s cached: a 52.37% observed reduction in this
small campaign. Median host first-3D times were 84.692/60.032 s; median F10P times
were 128.691/80.964 s. Report these separately. The hot/warm pairs are single
observations, not a performance conclusion. Large differences between receiver
TTFF and host observation remain recorded, rather than replaced by estimates.

Each cached trial accepted 60 current-day GPS/Galileo MGA-ANO entries and one
independent coarse time message, with no rejected/unacknowledged frames. No
unsupported BeiDou aid was injected. Receiver-retained Autonomous/flash data was
not proven absent, so these are **no-external**, not proven fully unassisted,
trials. RF and retained-data equivalence is not established.

The actual database boot hook accepted 159 DBD entries plus coarse time and
reported TTFF 7.020 s, host first 3D 17.047 s and valid UTC 28.035 s. Paired F10P
recovery was observed; its exact time was not captured in that harness revision.

With public NTP sources temporarily offline, the cached boot hook used a recently
independently validated DS1307 coarse date. It accepted 61 aiding messages,
reported TTFF 46.696 s, valid UTC 49.230 s, host first 3D 102.242 s and F10P
109.154 s. All eight public NTP sources were restored online afterward. This
was a software cold start, not an RTC-only startup after complete power loss.
Coarse aiding never bypassed the F10N UTC/F10P pairing gate.

## Online, offline and storage evidence

Exactly one additional free Predictive HTTPS request downloaded 35,280 bytes
through the already selected uplink. Day totals became two Predictive requests,
70,560 downloaded bytes and 1 MiB conservatively reserved. Existing 72-hour
refresh, 1 MiB/day, metering permission, request suppression and backoff remain.
No extra request was made to work around the exhausted allowance. Live remained
disabled with zero requests and no paid consent/enrollment.

The fresh comparison's cached trial completed (TTFF 29.927 s); its Internet trial
stopped before reset because of the timestamp bug. There is no completed fresh
versus cached A/B performance claim. The fix passed the reproducing regression
and an isolated replay of the actual downloaded payload: 60 compatible frames
selected, old date still rejected, no real request, and production cache/quota
hashes unchanged. This replay is identified as such, not another live download.

An isolated network namespace exercised actual HTTPS failure without changing
the management uplink. Offline and failed-download states retained 60 usable
cached frames; missing cache permitted ordinary acquisition. Real malformed,
truncated, checksum-damaged, expired, wrong-identity/firmware and incomplete-count
copies were rejected before receiver access. Production data stayed intact.
Fixed JSON/CSV/text exports were checked on actual report copies for redaction.

the original release tag.
