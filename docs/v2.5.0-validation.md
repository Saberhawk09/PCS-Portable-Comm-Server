## Scope and compatibility

This additive release combines GNSS Intelligence, the five-section/SBAS page,
and acquisition/navigation management on commissioned v2.4.0 base
`55a1bd336c0dc50771480aa9afb78bedf2050f63`.
See the [page guide](gnss-page-guide.md), [acquisition runbook](gnss-acquisition.md)
and [installation/rollback](gnss-intelligence-install.md).

Manufacturer authority: [F10 SPG 6.00 protocol 40.00, UBX-23002975 R02](https://content.u-blox.com/sites/default/files/documents/u-blox-F10-SPG-6.00_InterfaceDescription_UBX-23002975.pdf).
Actual receiver: EXT SPGL1L5 6.00 (041e8a), hardware 000A0000, protocol 40.00.
CFG-RST masks 0000/0001/FFFF use controlled GNSS-only mode 02; stop/start use
08/09. Reset ACK is not required. Actual DBD capture/count/restore ACKs passed.
F10 suppresses dump-completion ACK unless ACKAIDING is enabled: the worker now
journals and temporarily enables that RAM setting, then restores it. No flash,
baud, constellation, orbit-error or TIMEPULSE writes occurred.

Host fix observation differs from receiver TTFF; neither substitutes for the
other. RF/retained-data equivalence is not established. Faster acquisition would
not establish improved absolute PPS accuracy.

Cached delivery accepted 60 current-day GPS/Galileo MGA-ANO frames plus one
independent coarse UTC message, zero rejected/unacknowledged, in 1.057 seconds.
Download latency was zero. No BeiDou assistance or precise-position aiding.
Independent time used two public NTP measurements already held by Chrony,
poll-aware bounded ages and conservative uncertainty. DS1307 cross-validation
was recorded. INI used unknown leap seconds and did not bypass F10N UTC trust.

Manual capture saved 220 complete DBD frames/17,316 bytes. Same-receiver restore

## Deployment and final appliance state

The exact additive 22-file manifest backs up eight modules, admission helper,
nine units, web renderer, root wrapper, sudoers and web unit drop-in. New modules:
`pcs_gnss_acquisition.py`, `pcs_gnss_maintenance.py`. Four new units provide
acquisition, recovery, optional shutdown backup and asynchronous boot refresh.

Initial activation automatically rolled back because the verifier incorrectly
expected the legacy redirect PID to survive its parent web restart. GPSD
survived candidate activation; restoring the older gate then restarted GPSD
through that older implementation. Corrected activation preserved GPSD PID
986117 and Chrony PID 917 through every trial and passive spectrum check.
Both naturally changed on the authorized reboot. No routine refresh resets or
restarts timing services.

Final hardware state: sole GPSD owner, `/dev/pcs-gnss-neo`, 115200 baud, GPIO26
kernel PPS, fresh valid UTC, PPS paired and selected `*`, Chrony F10P synchronized.
All 60 protected files retained hashes/modes/ownership. Manual/LAN position,
EM7565 GNSS-disabled configuration, uplinks, WireGuard and radio settings remain.
Post-boot self-test: ALL ENABLED CHECKS PASSED, zero failures/warnings; no failed
systemd units after initialization settled. An early boot self-test was premature;
an earlier Meshtastic scheduled-position age warning cleared on normal boot.

Seven-day cache, 72-hour refresh, metered permission, 1 MiB/day and two Predictive
requests/day are unchanged. Qualification made no download/paid request. Live
remains disabled without cost authorization. Credentials remain root-private.
The new policy file remains absent, preserving commissioned cache-only admission.
Capture/restore/shutdown qualification flags are admitted for this exact receiver;
operators may explicitly configure automation later.
