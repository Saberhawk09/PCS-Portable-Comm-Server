# PCS v2.4.0 validation

November 15, 2026. This record separates verified software/live behavior from
remaining physical acceptance. The operator authorized v2.4.0 publication with
the live authenticated admin-action check deferred and the physical limits below
retained. Automated authentication tests passed.

## Scope and compatibility

This release adds optional NEO-F10N USB positioning/UTC and GPIO26/pin37 kernel
PPS support. Existing installations default to legacy EM7565 operation. Explicit
enrollment and activation are required; source updates never switch receivers,
change boot configuration, send modem AT commands or initiate LTE data sessions.
Automatic receiver failover is not enabled. The primary UART remains allocated
to APRS, and manual position remains independent of timing validity.

The appliance has separately authorized F10/PPS commissioning and EM7565 GNSS
shutdown. GPSSEL remains dedicated (0), LTE MAIN/AUX settings are unchanged and
shared AUX reception is not a qualified backup. See the dated
[F10 evidence](gnss-pps-hardware-validation-2026-11-15.md) and
[modem state](em7565-gps-notes.md).

## Appliance reboot verification

Two authorized software reboots returned new kernel boot IDs and automatically
recovered F10 position, valid UTC and paired F10P selection. Protected-file hashes
were unchanged. The persistent receiver alias followed renumbering from ttyUSB3
to ttyUSB0, and GPIO26 remained input/no-pull. Raw, selected and trusted LAN
position services agreed without emitting coordinates; public diagnostics
contained a fresh, nonempty receiver projection and remained coordinate-free.
The legacy NMEA initializer was skipped.

After each reboot, all 151 samples in a 180-second passive observation retained
fresh valid UTC, advancing kernel pulses and synchronized F10P selection. Existing PCS self-test
returned exit 0, ALL ENABLED CHECKS PASSED and PCS STATUS: OK; no failed systemd
units remained. The operator confirmed normal LCD/matrix indications after the
first reboot. Initial Chrony acquisition was allowed to settle before each
observation. These checks do not establish absolute timing accuracy.

Kernel boot IDs were `f33cb0c9-f3f6-4ca1-afc2-2306f7c6f5c7` and
`8169a885-6f57-463b-9300-55ee9cd310a7`. Configuration hashes were unchanged
across each reboot.

## Modem GNSS shutdown and control-path recovery

Separate, exclusive AT readback verified GPSENABLE=0, GPSAUTOSTART=0 and no active
modem GNSS session after reboot. It did not issue GPSEND or rewrite settings, so
a startup GNSS failure was not hidden by reapplying the shutdown.

After the first reboot, the modem registered on LTE through its AT interface, but
its former MBIM control path timed out. Both a shared-proxy capability query and
a direct query on an unowned control port failed. Restarting ModemManager did
not restore MBIM. No cellular data session was started, no LTE settings were
changed, and the cause has not been established. The existing self-test's
registration check is insufficient to accept this control-path regression.
The operator separately authorized one modem-only `AT!RESET`. It was sent exactly
once and restored MBIM/cdc-wdm0 operation and LTE registration. Subsequent
exclusive, query-only readback verified GPSENABLE=0, GPSAUTOSTART=0 and fix
session NONE after the actual modem reset; settings were not reapplied.

The second PCS reboot recovered MBIM and LTE automatically, without another
modem reset. A shared-proxy MBIM device-capability query succeeded. Original
bands, modes, capabilities, operator and registration state matched the captured
baseline; no data session, antenna/diversity or USB-composition change was made.
ModemManager was enabled/active, temporary masks were absent and the legacy NMEA
port remained inactive and unowned. Physical cold-power persistence remains a
separate gate.

## Web deployment and regression

An installed backend still at v2.3.2 was identified during parity checks. The
candidate backend/static files were deployed with the standard web installer,
private backups and rollback. Authentication hashes and protected GNSS, timing,
location, uplink and radio service processes were preserved. All 13 checked
installed files matched the candidate. No full base installer was run.

The live login page and public diagnostics were checked. The operator explicitly
deferred the authenticated live admin action. Automated authentication, CSRF,
no-JavaScript form and routing tests passed; they do not constitute an operator
login/action test.

## Remaining physical gates

Software reboot is distinct from removing power. Simultaneous cold start and
other power sequences, receiver PPS voltage/edge measurements, physical
antenna/PPS loss and recovery, and independent precision-reference/LAN accuracy
measurements remain unaccepted. Do not equate small Chrony residuals or software
fixtures with absolute physical timing accuracy. Modem GNSS disablement was
verified after an actual AT reset; a physical modem cold-power cycle is distinct.

No new radio transmission, cellular throughput run or RF acceptance is included.
Unchanged APRS/Meshtastic/Pi-Star services are checked passively; their existing
operator-supervised field gates remain separate. See the
[commissioning runbook](gnss-pps-commissioning.md) and
[release checklist](release-checklist.md).

`/var/backups/pcs-v240-web-qwk1eir4/`. The first directory retains the initial
